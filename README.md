# Frontline Map Duel Online — два игрока и сервер

Это самостоятельный веб-проект. Не открывайте `index.html` из архива двойным нажатием: он должен обслуживаться из `server.js` (иначе комнаты не работают). Установка npm-пакетов не нужна: Node.js 20+.

## Локальный запуск на компьютере

```bash
node server.js
```

Откройте `http://localhost:3000`. Устройства в одной Wi-Fi сети могут подключаться по `http://IP-КОМПЬЮТЕРА:3000` (возможен запрос на разрешение в брандмауэре). Запуск через `npm start` делает то же самое.

## Публичный онлайн-сервер через Render

1. Распакуйте папку и загрузите **её содержимое** в новый репозиторий GitHub. В корне должны быть `server.js`, `package.json`, `render.yaml` и `public/index.html`.
2. На render.com создайте **New → Web Service**, подключите репозиторий (не Static Site).
3. Runtime: Node; Build Command: `echo "No dependencies"`; Start Command: `npm start`; бесплатный тестовый тариф можно выбрать при наличии.
4. Подождите выдачи адреса вида `https://<ваше-название>.onrender.com`; откройте его.
5. Игрок 1 выбирает имя и сторону, нажимает **Создать комнату**, затем **Поделиться ссылкой**. Друг открывает ссылку, вводит имя и нажимает **Присоединиться**. Игровые действия передаются на сервер; второй игрок видит их без перезагрузки.

**Важно:** это исходники сервера, а не уже развернутый публичный адрес. Разместить в аккаунте хостинга должен владелец аккаунта. Бесплатные хостинги могут отключать процесс без трафика; на бесплатном Render локальные данные `data/rooms.json` могут пропасть при перезапуске/сне. Для надёжного постоянного хранения нужна постоянная дисковая память или отдельная БД. В игре есть кнопка экспорта партии.

## Как играть

- Только два участника; первым ходит создатель, второй подключается по коду/ссылке.
- Один ход — один полигон, прямоугольник, продвижение или пропуск, после чего сервер переключает очередь.
- Продвижение должно соприкасаться с уже нарисованной зоной **этого же** игрока. Сначала создайте стартовый полигон.
- Стороны обозначаются синим и красным. Новые полигоны просто визуально накладываются, это игровая карта, не геодезический учёт площади и не заявление о реальном положении на местности.
- Слой общедоступных данных из стороннего зеркала DeepState подгружается отдельно, дата снимка всегда показывается. Нанесённые игроками зоны никак не меняют исходный слой.
- Код комнаты состоит из 6 знаков; браузер сохраняет индивидуальный ключ игрока для возвращения после обновления страницы. Другу отправляют **ссылку с кодом**, не ключ из хранилища.
- Онлайн-режим требует интернета для сервера, карты, спутниковых тайлов и стороннего источника данных.

## API и развёртывание

- `GET /api/health` — статус сервера.
- `POST /api/rooms` — создание комнаты с `{name,side}`.
- `POST /api/rooms/:code/join` — вход второго игрока.
- `POST /api/rooms/:code/resume` — восстановление с `{token}`.
- `GET /api/rooms/:code/events?token=...` — обновления через Server-Sent Events.
- `POST /api/rooms/:code/action` — ход `{token,action:{type,shape,points}}`; очередь и геометрия проверяются сервером.
- `GET /api/rooms/:code/export?token=...` — сохранить снимок партии.
- `GET /api/frontline` — отдельно кэшированный слой стороннего зеркала с датой снимка.

Для постоянного диска задайте `DATA_DIR` на доступный сохраняемый том; без него используется `./data`. Не запускайте несколько независимых копий сервера на одном адресе без общего хранилища/координации комнат.
